## 二、根因假设（按优先级）

### H1：`RS_ENABLE_GPU` 打开但无 GL/VK 后端，应用侧 drawable 生成失败

证据链：

1. 产品配置 `ace_enable_gpu=true` → `rs_enable_gpu=true` → `render_service_base` 和应用侧都定义 `RS_ENABLE_GPU`。
2. 应用侧 `RSRenderNode::InitRenderParams()` 在 `RS_ENABLE_GPU` 下调用 `OnGenerate`。
3. Drawable generator 注册在 `librender_service`（服务端），应用只链接 `librender_service_base/client`，因此 `RS_NODE/ROOT_NODE/CANVAS_NODE` 在应用进程无 generator。
4. 应用无法生成 drawable → 窗口表面拿不到有效帧 → RS 的 `SURFACE_NODE` `Frame` 无效、`layerIdMap_` 为空 → composer 黑屏。

验证实验（已执行，失败）：

关闭 `graphic_2d_feature_ace_enable_gpu` 后 `images` 目标无法编译，当前 `graphic2d/0001`
补丁没有覆盖完整的 no-GPU 路径。主要错误：

- `rs_render_service.cpp`：`RSFilterCacheManager` 只有前向声明；
- `rs_main_thread.cpp`：`RSUniHwcPrevalidateUtil`、`needDrawFrame_`、
  `doDirectComposition_`、`needPostAndWait_`、`isLastFrameNeedPostAndWait_`
  未声明或受 `RS_ENABLE_GPU` 保护；
- `rs_render_service_connection.cpp`：`renderThread_` 成员缺失，
  `GetScreenSupportedModesExt` 返回类型不匹配。

已把 `ace_enable_gpu` 恢复为 `true`，并用 GPU-on 配置重新构建成功，保持工作区可构建。
下一步不是简单再关全局 GPU，而是二选一：

1. 补齐 no-GPU 声明（工作量较大，需逐文件 `#ifdef`）；
2. 拆分应用/服务端：保留 `librender_service` 的 GPU drawable 路径，
   让应用侧 `render_service_base` 不执行 `InitRenderParams` 的 drawable 生成

验收不变：应用日志不再出现 `RSRenderNode::InitRenderParams failed`；
`SURFACE_NODE` 有有效 `Frame`，`FrameBufferSurface` 有 buffer；

- 板测确认 `RegScreenRefresh` 成功且抓图非黑。

该库只用于并行合成（`RSInnovation`），而产品已关闭并行渲染。`gpuContext null` 更可能来自无 GL/VK 后端，而不是这个库本身。先做 H1，再判断是否仍需打包该库。

## 八、日志追溯结论（2026-11-17 补充）

### 1. access_token `magic fail, TYPE=84` 是误报

- 内核日志每 60 秒出现两条：`access_tokenid_ioctl: access tokenid magic fail, TYPE=84`
- `TYPE=84` = `0x54` = `'T'`，对应 Linux termios 的 `TCGETS`（`0x5401`），
  不是 access-token 的 `'A'` magic。
- 说明有进程对某个指向 `/dev/access_token_id` 的描述符做了 tty 探测
  （`isatty`/`control_fd` 路径），内核驱动把无关 ioctl 当成了 ABI 错误。
- 修复：`patches/kernel/0006-accesstoken-ioctl-noise.patch` 改为返回
  `-ENOTTY`，不再 `pr_err` 刷屏；access-token 真实 ioctl 仍按 `'A'` magic 处理。
- 结论：这不是 access-token 功能故障，不能据此判断 token ABI 坏了。

### 2. BootAnimation/视频路径失败可追溯

- `hilog-current.txt:3484`：`AllocSurfaceBuffer failed`
- `:3486`：`FCodec Start codec failed: cannot allocate buffers`
- 前置日志：`libdisplay_buffer_vdi_impl.z.so` 加载失败，metadata service
  `RegisterBuffer` 空指针，`surface_buffer_impl Alloc RegisterBuffer Failed`
- 根因：buffer HDI 服务按短名加载 VDI，但默认库只装在
  `/vendor/lib64/chipset-sdk/libdisplay_buffer_vdi_impl_default.z.so`，
  不在服务的默认 linker 路径。
- 修复：镜像组装时把该库同时注入 `/vendor/lib64/libdisplay_buffer_vdi_impl_default.z.so`
  和 `/vendor/lib64/libdisplay_buffer_vdi_impl.z.so`，verifier 覆盖两个路径。
- 这解释 bootanimation 视频/编解码失败；切换 bootpic 配置后可不走视频。

### 3. 黑屏的直接链路

- `hilog-current.txt:3342/3343`、`:12639/12640`：应用/系统进程
  `RSRenderNodeDrawableAdapter::OnGenerate`（type 1/4225/129）失败，
  `RSRenderNode::InitRenderParams failed`。
- `:56.178`：`Composer: Repaint: PreProcessLayersComp failed, ret is -3`
  （`layerIdMap_` 为空，见 `hdi_output.cpp:421`）。
- 板端 dump：`SURFACE_NODE[ScreenLockWindow] Frame[-inf]`、
  `VisibleRegion [Empty]`、`FrameBufferSurface` 队列为空。
- 关联：客户端只链接 `librender_service_base`，没有 `librender_service`
  的 drawable generator；`graphic2d/0003` 已让客户端跳过 drawable 生成，
  服务端在 `RSRenderService::Init()` 显式打开。是否解决黑屏仍需刷写验证。
